## 单变量裁决

- 中位 `35,000.8 → 31,689.2`，相对直接父对照回退 **9.46%**；三轮按轮比较分别为 **-26.45% / -11.79% / -9.46%**，全部超过“任一轮不得退化 >2%”门槛。
- 总 attempted 下降 **16.14%**，committed 下降 **16.75%**；异常放弃率只增加 **0.49 个百分点**。Rank 下降主要表现为固定窗口内服务能力降低，不是 abort 口径突变。
- CPU 平均下降 **19.95%**，平均延迟上升 **22.56%**，p99 上升 **45.26%**；R1 的 5s CV 还由父对照的 3.72% 升到 36.40%。这是等待或调度侧退化的外观，不是 CPU 算力打满。
- S1 的峰值 RSS 比父对照低约 10%，符合少维护 `recent_writes_` 元数据的方向；但资源下降没有转化为 Rank，不能作为上线理由。
- S1 的可选 I/O 窗口记录到 12,759 次 `fdatasync`、合计 54.038s；父对照该阶段采集失败，因此不能据此把回退精确归因到 WAL、锁或某个系统调用。

## 归因边界与处理

`5ff73a6` 只修改事务管理器 13 行，让 SI 写事务跳过 `recent_writes_` 插入。从机制上看，它减少一次互斥与集合维护；本次报告却出现整体服务能力下降。相邻单变量官方结果足以判定“没有可接受的 Rank 收益”，但单份 OJ 指标不足以证明这 13 行必然直接导致 WAL 等待或调度抖动，也不值得为解释负收益继续消耗正式评测次数。

处理如下：

1. `oj_split_S1` 从未合并到活动主线，`c446377` 的 **40,264.8 NewOrder/min** 继续作为性能回退锚点。
2. 不对 `oj_split_S1` 修补或复测；本地与 GitLab 远端 `oj_split_S1` 分支均已删除，远端引用已复核为空。负收益证据只保留在本文档与提交哈希 `5ff73a6` 中。
3. 后续独立候选不得叠加 S1；继续从不含该实验的 `0bfab08` / 对应干净父代码出发。
4. 历史 S1 `col_delta` 保持冻结有效，本次裁决不影响它。
