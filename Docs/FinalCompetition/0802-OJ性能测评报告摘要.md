## H4 冻结证据

1. `ser_finish` 改为接收调用方在 `rts_latch_` 临界区内计算的 `gc_watermark`，不再自行读取 `active_rts_`。
2. commit 传入安全的 `phys_wm`；abort 在移除自身 `read_ts` 后计算 `min(active_rts_min, published)`。
3. `rts_latch_` 与 `ser_latch_` 不嵌套。
4. 本地 H4 16×200 SER 事务连续 20 轮（64,000 事务）PASS；TSan H4 PASS、无 race 报告。
5. 功能 11/11、C1/C2/H3/H4/H5 5/5 PASS。
6. 同提交同机 W=5 SI mid A/B：未修 4,137.05，修后 4,138.23，变化 **+0.0285%**。
7. `5ae93e4` 官方 W=50×32 全流程 PASS。

**冻结裁决**：保留 H4 实现，不再继续修改 `ser_finish` / `active_rts_` 锁域。仅在出现新的 SER 正确性反例、TSan race、锁序问题，或同提交受控 SI A/B 退化超过 1% 时解冻。32.36% 异常放弃率与长窗抖动进入后续独立性能归因，不作为解冻 H4 的理由。
