## 一句话

决赛 = **必通过正确性门禁（过则 Score=100，不过=0）** + **TPC-C 饱和负载排名（NewOrder/min 中位数）**。  
一切优化不得破坏 ACID；不得依赖表名/SQL 硬编码；排名固定用 **SNAPSHOT ISOLATION**。

## 0. 术语与四类要求

### 0.1 关键术语（官方）

| 术语 | 含义 |
|------|------|
| 测评系统 / 测评程序 | 官方编译、功能、性能、恢复与出报告的系统 |
| 必通过项 | 任一未过 → **不形成有效性能成绩** |
| 成功提交事务 | 已收到 COMMIT 成功响应且满足事务与持久性要求（报告字段可写 committed） |
| NewOrder 成功提交速率 | 笔/分钟；报告字段 `NewOrder/min` |
| 事务归属仓库 | 路由器为每笔事务选的 home warehouse；**重试复用首次选择，不换仓** |
| 业务预期回滚 | NewOrder 无效商品等主动触发且应完整回滚的路径；**不计成功、不算故障** |
| 逻辑标识符 | 本文用的表名/列名；运行时可做等价不透明替换 |

协议标签、报告字段、SQL 标识符保留英文原文；其余用上表中文术语。

### 0.2 四类要求

| 标签 | 含义 |
|------|------|
| **规范要求** | 无论自动测是否覆盖，必须遵守 |
| **自动门禁** | 测评直接检查；失败则终止或该次性能 **0** |
| **审查性红线** | 日志/源码/复核确认即违规，成绩无效 |
| **优化建议** | 只影响排名；**不得**被解释为允许降低 ACID |

冲突时：**规范 / 红线 > 建议**。自动门禁是规范的可执行子集，**不缩小**规范适用范围。  
「自动测没检出」≠ 可以违反说明。

### 0.3 基本规定（摘录）

1. 负载：TPC-C **5.11** 兼容饱和；榜指标 = NewOrder 成功提交速率（笔/分钟）。
2. 功能正确性 / COMMIT 持久化 / 崩溃恢复 **任一未过** → 不进性能评分，得 **0**。
3. SQL、答案、种子、运行时标识符、隐藏校验、完整日志等 **不向队伍公开**；失败报告仅脱敏阶段/类别/可公开序号与已确认事实。
4. 【规范/红线】编译与 rmdb 以专用非特权身份跑；**不得**修改、探测、依赖测评资产内部实现。
5. 【规范】正式库 **不透明** 库名/表名/列名/CSV 名；建表/索引/装载/校验顺序 **非固定**；不得依赖公开 TPC-C 名、固定客户端数或「请求不会交错」。
6. 【规范】统一 **RMDB Wire Protocol**；功能/恢复/装载/大查询走 `EXEC_STREAM`；排名走 `PREPARE_SET` + `EXEC_BATCH`；**不读 `output.txt`，不发 `SET OUTPUT_FILE`**；排名前语义预检失败不进计时。
7. 每次启动/崩溃重启须 **SQL 测活**：预期进程树监听端口 + Wire 成功执行 `show tables;`（空库 0 行 OK）；仅 TCP 连通不算就绪。

正式测评由组委会驱动，**不另发可独立跑的官方性能客户端**；完整字节规范见 **附件 A**。

## 1. 成绩怎么算

| 项 | 规则 |
|----|------|
| Score | 全部必通过项过 → **100**；任一不过 → **0** |
| 排行榜 | 3 个正式窗口的 **NewOrder 成功提交速率**中位数（笔/分钟），高者靠前 |
| 公式 | `成功 NewOrder 数 / 窗口秒数 × 60`（默认窗口 **150s**） |
| 有效性前提 | 混合比、计数一致性、客户端规模、数据规格、在线一致性、崩溃后校验均须满足 |
| 诊断列（不排序） | abort-rate、p50-ms、p99-ms、max-rss(GB)、disk-usage(GB)；CPU 均/峰仅参考 |

### 必通过项（缺一则性能 0）

1. **功能正确性**（含 SI/SER、COUNT(DISTINCT)、FLOAT 等）
2. **COMMIT 持久化校验**（ACK 前可核验的 WAL 稳定化）
3. **崩溃恢复测试**
4. **性能测试全程正确**（装载、在线一致性、恢复后校验等）

读写诊断（strace）**不计分**；采集失败只 **WARN**，已形成 Score/榜不变。

### 成绩无效的常见情形（含但不限于）

1. 事务计数一致性失败，或某正式轮某类事务 **0 成功提交**
2. 客户端数或数据规模不符（正式 **32** 连接 + 正式数据规格）
3. 在线一致性未过
4. SIGKILL 后成功提交丢失或恢复错误
5. 延迟与成功提交统计明显不一致、无法校验  
禁止用截断/伪造/错序 Wire frame 规避校验。

## 2. 测评流程（固定顺序）

```
编译与服务启动
 → 功能正确性
     ├ 通过 → COMMIT 持久化校验
     └ 未过 → 跳过 COMMIT 校验
 → 崩溃恢复（无论功能是否过都跑，作诊断）
 → 汇总：任一必通过不过 → 性能 0，结束评分路径
 → 性能测试
     装载正式数据 → 预热 30s（不计分）
     → 3×150s 正式测量
     → 在线一致性（三窗结束后、杀进程前）
     → 算 NewOrder/min 中位数
     → SIGKILL（保留数据目录）→ 90s 内重启恢复
     → 恢复后一致性/持久性
 → 读写诊断（仅必通过全过）：复用恢复后库；10s 预热 + 60s strace 同规格负载
 → 清理结束
```

要点：

- 功能不过时仍跑恢复用例作诊断，**不改变**已失败的必通过判定。
- **排名前**崩溃恢复重启预算 **60s**；**排名后**强制杀进程再启预算 **90s**。
- 排名负载 **仅一次** 30s 预热；窗口间不再预热。
- CPU：单核 100%；多线程可 >100%；只作诊断。

### 学生可见反馈边界

公开：判定、得分、榜指标、分阶段报告；失败时 `Failure category` / `Failed substage` / 脱敏 `Key fields`；协议失败可给固定 **Protocol constraint** 文案（不回显实际 tag 数值）。  
一致性例外：允许列表检查名、期望值、实际值、tolerance；严格 FLOAT32 用 `0x????????` + **0 ULP**。  
**不公开**：生成 SQL/答案、运行时表列名、内部路径、种子、隐藏校验、完整服务日志、逐条 strace。

报告阅读顺序：最早失败阶段 → category → substage → key fields；优先修 **首个可本地复现** 问题。

### 3.2 热点轮盘（规范细节）

- 隐藏 workload seed 派生 **4** 个热点仓；每热点仓占 **26** 槽；其余 46 仓各 ≥1 槽；另有 **10** 冷仓每阶段各 +1 槽。
- 槽内容按阶段独立洗牌；热点仓身份整次测评不变。
- 客户端 **5 波**覆盖 160 槽，**非**固定终端仓库：

```
slot_index(client_id, txn_no)
  = (client_id + 32 × (txn_no mod 5) + 13 × floor(txn_no / 5)) mod 160
```

- `client_id ∈ [0,31]`；`txn_no` 每阶段从 0 起，选出参数时递增；**最终放弃的事务也占序号**；重试不增序号。
- 连续 5 波覆盖全部 160 槽；13 与 160 互素，避免卡在同一槽组。
- 热点仓 / district / 商品 / 阶段轮盘使用与事务参数随机流 **隔离** 的路由随机域。
- 【规范】可重试冲突 **复用** 首次归属仓、district、商品、供货仓、远程客户与客户选取方式；不重抽、不换仓改覆盖统计。
- 【规范】必须在真实多客户端交错下处理 `d_next_o_id`、热点 stock、Delivery 领取等冲突；不得只优化 NewOrder。  
  【建议】粗锁本身不算正确性失败，但伤吞吐。  
  【红线】取消冲突检测 / 跨事务共享可变状态 / 未提交对外可见 → 正确性失败或成绩无效。

### 3.3 仓库覆盖门禁

| 条件 | 要求 |
|------|------|
| 单轮完成样本 ≥400 | ≥**45/50** 归属仓出现完成事务，且 **4 个热点仓全覆盖** |
| 三轮合并 ≥400 | **50/50** 且覆盖全部热点仓 |
| 样本 &lt;400 | 最低覆盖仓数 = `ceil(完整要求 × 完成数 / 400)`；**不强制**「全部热点仓」 |

「完成事务」= 成功提交 + **业务预期回滚**；不含放弃、截止停止、窗口后 grace-tail。  
报告公开每轮及合并覆盖仓数；完整 50 仓直方图与热点比例仅后台。

## 4. 五类事务语义

| 事务 | 必须做对的事 | 理想无重试 batch RTT |
|------|----------------|----------------------|
| **NewOrder** | 分配订单号；写 orders / new_orders / 全部 order_line；更新 stock；任一明细失败整笔回滚 | **2**（锁库存→写/COMMIT；无效商品在第二 batch 写有效明细后 ABORT） |
| **Payment** | 更新 w/d/c，插 history；按姓名取客户用 **中位**规则 | **2** |
| **OrderStatus** | 最近一笔订单 + 全部明细；`o_entry_d` 非空；`o_carrier_id` ∈ [0,10]（TPC-C 2.6.2.2） | **3** |
| **Delivery** | 各非空分区取**最早**未配送；空分区跳过；`SUM(ol_amount)` 加余额；同步 new_orders/orders/order_line/customer | **2～3** |
| **StockLevel** | 最近 20 单相关库存中，低于阈值的**不重复商品数** | **2** |

补充硬约束：

1. 无效商品 = **业务预期回滚**；回滚后不得残留堆/索引；**不计** NewOrder 成功数；异常中止/协议失败/超时/放弃 **不得**冒充业务回滚。
2. Stock 必须相对更新；客户端按 `(supply_w, item)` **升序去重加锁**再按原明细序更新（防热点反序死锁环）。
3. Delivery 不得任意选取；全空可正常 COMMIT，但每正式窗须有 ≥1 笔 **实际处理**排队订单。
4. OrderStatus「最近」与 Payment「中位」依赖稳定排序。
5. StockLevel：**只发单条** `COUNT(DISTINCT …)`，无客户端去重兼容路径；须解析 `COUNT(DISTINCT col)` 与 `COUNT(DISTINCT (col))`；阈值比较为 **`s_quantity < threshold`**（等于不得计入）；须多仓隔离 + join 扇出去重。

按 45/43/4/4/4，理想无重试加权约 **2.08 batch RTT/事务**。  
隔离设置与 `PREPARE_SET` 在测量开始前完成，**不计入**测量窗。

本地 StockLevel 形态参考：

```sql
select count(distinct (s_i_id)) from order_line, stock
 where ol_w_id = ? and ol_d_id = ? ... and s_quantity < ?;
```

## 5. 决赛功能新增 / 加严点

### 5.1 可配置隔离级别（功能门禁）

会话级（连接建立后、首个 BEGIN 前设一次，持续作用于后续事务；**不是**一次性 next-txn）：

```sql
SET TRANSACTION ISOLATION LEVEL SNAPSHOT ISOLATION;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

均应返回 `COMMAND_OK`。除配置语法测外，同一语义点多连接只用同一种隔离级别。

功能历史约 **48** 个：配置 3 + SI 18 + SER 27。

- **SI**：事务级 MVCC 快照、本事务写可见、提交/回滚、同逻辑记录写写冲突。
- **SER**：在 SI 上检查记录读、谓词读、空结果范围读与 rw 反依赖。

**SSI 赛题额外协议（严于通用可串行化）**：若当前语句（SELECT/INSERT/UPDATE/DELETE）新增 rw 反依赖并形成危险结构（含 record/predicate 写偏序及题面多事务危险组合）→ **当前语句立刻** `TRANSACTION_ABORT` 并回滚；**禁止拖到 COMMIT 再裁决 / 换 victim**；不得以「结果仍可串行化」免责。

TPC-C 排名连接固定 **SI**，且在安装 `PREPARE_SET` 前完成设置。

### 5.2 COUNT(DISTINCT)

引擎必须原生支持（含多表 join + 过滤）；排名启动会探测，失败则不进计时。正式排名与非计分 I/O 诊断复用同一套服务端实现。

### 5.3 FLOAT（binary32）

| 规则 | 内容 |
|------|------|
| 表示 | IEEE-754 binary32；`round-to-nearest, ties-to-even`；+0/-0 同值；禁 NaN/Inf |
| 相对加减 | 每次 SQL 更新处做一次 binary32 加/减并舍入；Payment/Delivery **0 ULP**；失败报告给 Before / Bound amount / Expected / Actual / Tolerance（十进制 + `0x????????`） |
| SI 陈旧写 | 依据过期版本更新 → 必须 `TRANSACTION_ABORT`，不得写到新版本上 |
| SUM(FLOAT) | 各 binary32 → binary64 累加 → **一次**舍入回 binary32；**不规定** binary64 累加顺序 |
| 大账本 SUM | 排名量级 `SUM(h_amount)` / 新订单 `SUM(ol_amount)`：先精确和 S 与误差上界 ε≈`n·2⁻⁵³·S`，接受 `[S−ε,S+ε]` 舍入到 binary32；仅当 S 落在舍入边界邻域才可能接受相邻值 |
| 仍 0 ULP | 单笔相对加减、单订单 `SUM(ol_amount)`（≤15 行）、`SUM(s_ytd)` 整数量累计 |
| Delivery 账本 | 按每个 `ol_amount` **实际 binary32 位值**扩成 binary64 累加；**不**先量化为整数分再重建；客户端同时 `SUM(ol_amount)` 与逐行复算 **0 ULP**，并把该 SUM 原样绑定到 `c_balance = c_balance + ol_total` |
| Wire | 传 bit pattern，不再比六位小数文本；六位小数仅用于测评生成的 SQL literal |
| 排名 NewOrder | 价格×数量由测评算好后以 prepared FLOAT32 绑定；**不要求**引擎支持投影中的浮点乘除 |

崩溃前后七项金额聚合：

- **0 ULP**：`SUM(w_ytd)`、`SUM(d_ytd)`、`SUM(s_ytd)`
- **≤1 ULP**：`SUM(c_ytd_payment)`、`SUM(h_amount)`、`SUM(c_balance)`、新订单 `SUM(ol_amount)`（扫描顺序不受约束；丢一笔提交金额偏移通常数百～数万 ULP，仍可检出）

### 5.4 Wire Protocol（与旧 NUL/`output.txt` 不兼容）

| 路径 | 用途 |
|------|------|
| **EXEC_STREAM** | 功能 / 恢复 / DDL / 装载 / 大查询 |
| **PREPARE_SET + EXEC_BATCH** | 排名高频路径 |

要点：

- 握手：`RMDB` + major=**3**, minor=**0**，原样回送；不支持则关连接，不得把握手当 SQL
- 通用 frame：`u32 payload_bytes | u8 tag | u8 flags | u16 reserved=0 | payload`；payload ≤ **1 MiB**；大端序；循环读写完整 header+payload
- 同连接一个 outstanding request；无 pipeline / request id / 乱序；batch 内严格顺序
- 不读 `output.txt`，不发 `SET OUTPUT_FILE`
- 测活：端口由预期进程监听 + `show tables;` 完整成功（空库 0 行 OK）
- `show tables` / `desc` 在 Wire 下走 **META → ROW\* → RESULT_END**（与 `COMMAND_OK` 不可互换）
- **PREPARE_OK** 每 query 列数/顺序/类型须与实际投影一致；禁止单占位列顶替未读投影列
- **AUTO_ABORT**（`EXEC_BATCH` flags bit0=1）：任一 op 失败 → 先回滚再回失败 `BATCH_RESULT`；失败 batch **无部分查询结果**
- 可重试冲突用 `TRANSACTION_ABORT`，客户端直接重试，**不再发第二次 ABORT**；不可重试用 `ERROR`
- NewOrder 无效商品：第二 batch 写入此前有效明细后 `ABORT`，用于校验 prepared 路径完整回滚
- 类型：`0x01 INT32` / `0x02 FLOAT32` / `0x03 CHAR`；cell 用 `present` 0/1；正式负载 **不要求 SQL NULL**（未配送整数用 0，时间戳用空串）
- `$1..$n` typed bind；单引号内 `$n` 是文本；CHAR 勿未经转义拼回 SQL
- 实现建议（非额外评测）：连接级字典；1 MiB 内 buffer；按 fingerprint 共享只读 plan 但隔离连接态；硬上界 + 背压

**Tag 速查**

| 方向 | tag | 名称 |
|------|-----|------|
| C→S | 0x20 / 0x21 / 0x22 | EXEC_STREAM / PREPARE_SET / EXEC_BATCH |
| S→C | 0x01 / 0x02 | META / ROW |
| S→C | 0x10 / 0x11 / 0x12 / 0x13 | COMMAND_OK / RESULT_END / TRANSACTION_ABORT / ERROR |
| S→C | 0x14 / 0x15 | PREPARE_OK / BATCH_RESULT |

**BATCH_RESULT status**

| status | 含义 | 约束摘要 |
|--------|------|----------|
| 0 OK | 成功 | executed==count；failed=0xffff；每 query 恰一结果集 |
| 1 TRANSACTION_ABORT | 可重试 | executed&lt;count；failed==executed；result_count=0；已回滚 |
| 2 ERROR | 不可恢复 | 计数同 abort；result_count=0；已回滚 |

`executed_operations` = 失败 op **之前**已尝试、但效果已随事务回滚的数量；失败 op 本身不计入。

**本地探针 / 测试**

- 探针：`python3 tests/local/wire_readiness_probe.py`（须先起 `./bin/rmdb <db>`）
- 功能 / 一致性：`wire_client.py` + `EXEC_STREAM`；`run_tests` / C1/C2/H5 已默认 Wire
- 排名路径：`tpcc_batch.py` 默认 `PREPARE_SET + EXEC_BATCH`；相对 FLOAT；混合比 **45/43/4/4/4**
- 档位：`--mid`（60s×3 / 16）趋势；`--finals`（150s×3 / 32）OJ 形（本地仍 W=5 CSV）
- A/B：`--stream` / `--legacy-mix`（初赛 10/23）
- 完整门禁：`bash tests/local/debug/run_full_local_gate.sh`

附件 A §8 实现核查表：read_exact/write_all；握手后只读 8 字节 header；成功 batch 不逐条 DML ACK；可 writev 聚合写但仍处理 short write；拒未知 tag/flag/type/尾随字节。

## 6. 正确性与持久性（成绩生命线）

### 6.1 在线一致性（3 窗口结束后、杀进程前）

固定 **6 项整数 + 7 项 FLOAT32** 快检；整数偏小表/索引键；FLOAT 采崩溃前 bit pattern 并与账本核对（stock 整数量 0 ULP；history/新订单 order_line 按边界感知）。  
**不做**大表全量扫描/逐行关系审计（留给恢复后）。

### 6.2 崩溃后

SIGKILL → 重启 →：

1. 已 COMMIT 可见完整；未提交不可见部分  
2. 不得重复施加不应存在的修改；日志/数据页/元数据一致  
3. **37** 整数 + **7** 金额聚合；七项 FLOAT 按 §5.3 两档与崩溃前 bit pattern 比对  
4. 核对账本样本；**全部 500** 个 warehouse/district 分区逐一核订单数、明细数、未配送队列、空配送时间行数、`o_carrier_id=0`、`d_next_o_id`  
5. **YTD 更新链**：按每笔已提交 Payment 的更新前/后值验证每个实际发生 Payment 的仓/区链，并核最终值（公开初值仍 `w_ytd=300000` / `d_ytd=30000`）

每个恢复用例一次 SIGKILL→重启→校验；「多次恢复稳定」建议本地做，**非**单用例内重复恢复门禁。  
COMMIT 持久化校验与崩溃恢复 **相互独立**；容器内 SIGKILL ≠ 整机断电。

### 6.3 COMMIT 持久化（可审计契约）

ACK 成功前，对应 WAL commit record 必须被**同一 ACK 窗口**内可核验稳定化覆盖：

- 有效：对 WAL 对象先有 **>0 字节写入**，再 `fsync` / `fdatasync` / `O_SYNC`·`O_DSYNC` / `RWF_SYNC`·`RWF_DSYNC` / 合法 `sync`·`syncfs`（syncfs 的 fd 路径须在**本次数据库目录**内）
- 无效：零字节写、只进 OS 缓存、关库后再刷、刷错文件、单独 `msync`、不可解码的 io_uring 等
- WAL 路径：`db.log` 或 `db.log.*` 或 `wal/**`，必须落在本次数据库目录内；`db.logger`、符号链接逃逸、目录外文件不算
- 新建/轮转 segment：首次用于覆盖 COMMIT 前须 fsync 父目录（跨目录重命名同步源+目标；新建 `wal/` 逐层）
- group commit 允许，但本校验负载 **顺序发 COMMIT**；不得先 ACK 多个成功再错开补同步

**“理论持久但测不到”不算过。**

### 6.4 读写诊断（不计分）

必通过全过后：10s 预热 + 60s strace 同规格负载。报告聚合：五类 Committed/Attempted/Commit rate；`/proc/.../io`；缺页与上下文切换；选定 syscall 的 calls/errors/耗时；Read/Write/Sync family 总数。  
**不**替代 COMMIT 持久化校验。

## 7. 红线与合规优化边界

### 7.1 ACID（强制）

任何性能路径（含 EXEC_STREAM / PREPARE·BATCH / 装载 / 预热 / 测量 / 诊断 / 恢复）不得降低原子/一致/隔离/持久；无「性能专用弱语义路径」。  
可观察等价：合法请求、冲突、业务回滚、连接异常、强制终止/重启下，提交结果、可见性、错误/回滚、Wire 状态、恢复后数据须符合同一契约。SSI 固定中止点/victim 除外（§5.1）。

| 属性 | 禁止示例（节选） |
|------|------------------|
| 原子性 | 部分写成功；只滚表不滚索引；AUTO_ABORT 失败前未回滚 |
| 一致性 | 省略某类事务/写集；过期缓存/预置结果；延后索引导致查不到已提交状态 |
| 隔离性 | 取消冲突检测；跨事务共享可变状态；未验证乐观提交；单线程/无交错假设 |
| 持久性 | 稳定化前 ACK；只写页缓存；刷无关文件；理论持久不可审计 |

### 7.2 反硬编码（强制 / 审查红线）

禁止按表名/列名/文件名/原始 SQL/SQL 哈希/固定 statement_id/参数组合/行数/客户端号/阶段名/进度等识别测评后走专用分支或预置答案。  
计划缓存、schema 索引、统计选计划本身合法，但必须绑定真实参数与数据，失败回退通用路径。`statement_id` 只能查本连接已安装语句，不能用来「认出测评事务」后跳过执行。

### 7.3 可以使用的优化方向（前提：满足 7.1–7.2）

解析/计划缓存、向量化、EXEC_BATCH 聚合写；索引与页缓存（须可见性与失效）；细粒度锁/MVCC；group commit / WAL 批量（稳定化后才 ACK）；后台写回/checkpoint（WAL 先行）；批量装载（成功时行数/内容/索引/持久完整）。

### 7.4 官方建议工作顺序

1. 正确性基线（五事务 + 回滚 + 恢复 + 大装载）  
2. 访问路径（索引，避免无谓全表扫）  
3. 并发（细粒度锁 / MVCC，保 SI 与热点更新）  
4. 持久化（group commit 等，须可审计稳定化）  
5. 减测量路径开销（禁关 WAL / 回滚 / 冲突检测 / 必要索引维护）

## 8. 常见问题速查（官方 §七 压缩）

| 现象 | 优先方向 |
|------|----------|
| COUNT(DISTINCT) 失败 | 联表后去重；`s_quantity < thr`；两种括号写法 |
| FLOAT 失败 | 按 Before/Bound/Expected/Actual 复算；0 ULP / ≤1 ULP / 边界感知分档 |
| COMMIT 持久化失败 | ACK 窗内：WAL 正字节写 → 同对象稳定化；新 segment 父目录 fsync |
| 恢复少/多数据 | ACK 前稳定化 + redo；undo 未提交；恢复幂等 |
| 装载超时/OOM/行数不符 | order_line 5～15 动态行；有界缓冲；分批 COMMIT；查 Load step / Table ordinal |
| setup / Wire 失败 | 附件 A：握手、8B frame、PREPARE schema、AUTO_ABORT、短读 |
| Unexpected txn abort | 测活/装载边界收到 ABORT；不可重试用 ERROR |
| Index entry already exists / 唯一约束 | `d_next_o_id` 并发；ABORT 后索引残留 |
| Consistency mismatch | 区分杀进程前 vs 恢复后；按第五章不变量本地复现 |
| Payment/Delivery 累计不一致 | 三项 YTD+history；最早未配送 + 同事务更新余额/队列 |

## 9. 参赛提交前自检清单（官方 §八）

**正确性**：全路径 ACID；五类边界；无效商品整笔回滚；表扫与任一索引可见性一致；`o_ol_cnt`↔明细；Stock 并发安全；Delivery 最早；StockLevel 单条 DISTINCT；Wire 握手/短读写/类型/空结果；PREPARE 原子字典；AUTO_ABORT 先回滚。  

**通用性**：换标识符/等价 SQL 写法/参数/规模/顺序/交错/故障时点仍正确；无测评专用分支。  

**并发与性能**：32 客户端下隔离正确；五类持续提交；每轮五类≥1 成功；Delivery 真处理；覆盖门禁；无过量死锁重试；合理索引；无逐事务冗余日志；多窗稳定。  

**持久化**：SIGKILL 后已提交在、未提交无；ACK 前可审计稳定化；WAL 命名/syncfs 边界；装载后重启过行数。  

**指标表述**：用 NewOrder/min；区分成功 / 业务回滚 / 放弃；看 p99 不只均值。
