## 2. 架构定稿

### 2.1 定稿口径

以 `c446377` 为答辩与交付基线，固定如下分层：

```text
接入层：TCP Server / Wire Protocol v3
查询层：Parser → Analyze → Optimizer → Portal → Executors
事务可靠性层：TransactionManager + SI/MVCC + SER/SSI + LockManager + WAL + Recovery
数据层：B+ Tree + Slotted-Page Record + Buffer Pool + Disk + Metadata
```

### 2.2 冻结边界

| 范围 | 裁决 |
|------|------|
| 系统分层、核心接口、SI/SER 语义、WAL 持久化契约、Wire v3、测试主流程 | **冻结** |
| 768MB BPM 默认配置、默认关闭 `RMDB_STMT_STATS`、当前性能基线 | **冻结** |
| P-A1、P-A2、P-A3、P-W1 等性能实验 | **不启动** |
| 17 日现场题所必需的最小改动 | 允许；必须附定向测试和基础回归 |
| CMake、表名/SQL 特化、降低 ACID 的“优化” | 禁止 |

若现场题需要触及多层，先画出 `Parser → AST → Analyze → Plan → Executor → Test` 的最小影响链；只有明确题意要求时才扩展到事务、存储或恢复层。

## 4. 8 月 17 日线下功能题作战流程

### 4.1 赛前训练要求

至少完成两到三次脱离 AI 的限时演练。练习题应覆盖陌生小功能，例如 SQL 语法/表达式、标量或聚合函数、Explain 输出、索引扫描条件、DDL/DML 语义或协议边界校验。

每次演练按固定闭环进行：

```text
读题并列出输入/输出/错误边界
  → 定位影响层与现有相邻实现
  → 编写最小实现
  → 编写定向 SQL / 协议测试
  → Release 构建与基础回归
  → 复盘遗漏模块、异常路径与测试缺口
```

### 4.2 现场分工与纪律

三名队员可分别承担需求与调用链定位、主实现、测试与边界验证；但每人都必须能独立解释完整链路，避免单点依赖。全程不用 AI，遇到不确定点优先读本仓库相邻实现、现有测试和赛事资料。

提交前最低检查：能编译、定向用例通过、已有基础用例不退化、错误返回符合题意、没有临时硬编码或调试输出。

## 5. 8 月 18 日答辩准备

### 5.1 第一轮：PPT 主讲

准备 8、12、15 分钟三个版本，核心内容保持一致：

1. 项目目标、官方结果与系统边界。
2. 总体架构与 SQL 执行链。
3. Slotted-Page、B+ 树、Buffer Pool。
4. MVCC、SI、SER/SSI 与锁管理。
5. WAL、组提交、COMMIT 持久化与崩溃恢复。
6. Wire v3 与决赛功能增量。
7. 性能优化的方法、有效项与淘汰项。
8. 官方正确性/恢复/性能证据。
9. P-A1 的冻结事实与不作过度归因的工程纪律。
10. 团队实际分工、总结与可验证贡献。

### 5.2 第二轮及后续：专家问答

每个回答遵守“结论 → 机制 → 源码/测试证据 → 局限性”顺序。重点覆盖：

- B+ 树唯一性、并发访问、分裂和扫描；
- Buffer Pool 的 pin/unpin、淘汰、脏页与并发；
- SI 陈旧写为何必须 abort，不能 rebase；
- SSI rw 反依赖与语句级立即 abort；
- INLJ 右表为何登记实例化谓词和命中 RID；
- `fdatasync`、组提交与 COMMIT ACK 的耐久性关系；
- analyze / redo / undo 的恢复顺序；
- 768MB BPM、WFG、版本链回收、`UPDATE_DELTA` 等取舍；
- 为什么淘汰固定 sleep 微批、纯 wait-die、SQL 特化；
- 40,264.8 的官方成绩如何得出，以及为何不把跨次波动归因给单个补丁。

**P-A1 统一回答**：诊断框架、确定性用例和 W=5 单变量证据已完成；正式 W=50 开启态取证因本机资源约束冻结。它不影响已经通过的功能、恢复、持久化和排名门禁，也不被包装为已验证的根因结论。
