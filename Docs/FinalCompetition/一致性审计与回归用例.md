## 二、P0 已修复（原稳定复现）

```bash
# 修复后门禁（应 100% PASS；勿用 --stability，该模式测的是「漏洞检出率」）
python3 tests/local/consistency/run_consistency_regress.py \
  --case C1 --case C2 --case H5
# 建议再连跑 10 轮，或：
for i in $(seq 1 10); do
  python3 tests/local/consistency/run_consistency_regress.py --case C1 --case C2 --case H5 || exit 1
done
```

| ID | 漏洞 | 修复要点（2026-07-14） |
|----|------|------------------------|
| **C1** | 堆先于 MVCC 链 | `RmFileHandle::reserve_insert_slot` → `mvcc_insert` → `publish_insert_slot`；bitmap 发布前登记版本 |
| **C2** | `pending` 未检 | `mvcc_other_writer` 对齐 `mvcc_write`，先查 `pending` 再查 `chain.writer` |
| **H5** | `mvcc_on_` 缓存 | SeqScan/IndexScan 每行重查 `table_is_dirty`；有活跃显式事务时 autocommit 写走 `needs_versioning` |
| （附） | DELETE 墓碑后行复活 | commit 时 `writer_del` 同步 `delete_record`，避免 prune 摘 tombstone 后堆仍可见 |

### C2 旧用例曾 PASS 的原因

单连接 `BEGIN` → SI fast path，未走 pending。须双连接先 `BEGIN` + `pre_dirty_table()`。

### H5 加强要点

不用扫描中途 INSERT；改为 **已存在行**（`id` ∈ 1..n_rows）的 committed UPDATE 后 SELECT。用例目标 id 已改为 `75`（原 `250` 超出种子行数会恒 skip）。
