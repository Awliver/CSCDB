## 回退记录（2026-07-09 晚 → 2026-07-10 确认恢复）

> **OJ 仓库**：平台配置为拉取 **`gitee/new_tpc_c`**（非 `origin/new_tpc_c`）。

| 项 | 值 |
|----|-----|
| 退化提交 | `0611879` 窗口设置（S5.2 默认 **80μs**） |
| 退化结果 | OJ tpmC **~950 → ~800** |
| 回退提交 | `9726c6a` 回退 S5.2 微批默认窗口至 0（关闭） |
| 回退结果 | OJ 复测 **tpmC 显著回升**（~950 附近，2026-07-10 用户确认） |
| 本地对照 | 本机 30s+360s×3 A/B 测出「−0.87%，噪声内」——**与 OJ 结果矛盾**，本机不能作为 `sleep_for` 类改动的上线依据 |
| 根因推断 | `sleep_for(80us)` 在 OJ 判题机（疑虚拟化/共享核）上实际唤醒延迟远超本机；`first_round` 几乎每批触发；详见 [§4 §0.2.2](./4.S5-WAL组提交深化.md#022-上线回退oj-tpmc-950--800-2026-07-09-晚) |

**结论**：S5.2 微批的固定时长 `sleep_for` 机制在 OJ 判题机上是明确的负收益，根因诊断（调度延迟被放大）成立。已回退，S5.2 暂缓，见 [§4 §0.2.2](./4.S5-WAL组提交深化.md#022-上线回退oj-tpmc-950--800-2026-07-09-晚) 的教训与后续方向。
