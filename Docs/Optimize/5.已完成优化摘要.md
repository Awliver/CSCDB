## 0. 状态说明

| 标记 | 含义 |
|:---:|------|
| ✅ | 已落地、当前默认生效，并随当前官方 PASS 基线运行 |
| 🧊 | 已落地但收益有限、排名路径不相关，或原瓶颈已消失；保留并冻结 |
| ⚙️ | 机制仍在代码中，但默认关闭；不能算已证明有效 |

“随整版通过”只证明没有观察到整体回归，不证明每一项都有独立收益。单项证据只采用同机 A/B、profile 闭环或明确错误复现。

| 项 | 当前实现与证据 | 状态 |

| **768MB 缓冲池** | `BUFFER_POOL_SIZE=196608`；官方峰值 RMDB RSS 1.91GiB 下完成三窗 | ✅ |
| 后台 Page Cleaner | 低空闲帧时刷 `pin==0` 脏页，避免前台集中刷写 | ✅ |
| S6 evict 分片 | 每分片 `free_frames_`，移除全局淘汰热点 | ✅ |

## 7. 已清退项

| 项 | 原因 | 当前处理 |
|----|------|----------|
| district / warehouse / SQL 文本特化 | 违反标识符不透明与通用性要求 | 代码已删除，不得恢复 |
| 固定 `sleep_for(80us)` WAL 微批 | OJ 明确负收益 | 默认 0，仅留历史复现入口 |
| 纯 wait-die | 大量误 abort、吞吐崩塌 | 由 WFG 取代 |
| 单连接 SI 物理快路径 | 可观察未提交物理写，造成脏读 | 已禁用 |
| SI 陈旧写 rebase | 违反 SI first-committer-wins | 已改为 abort |
| 1GB BPM 决赛默认 | 2GiB 限制下内存悬崖风险 | 当前固定 768MB |
| 批量全库“洗注释” | 无性能收益、审计噪声大 | 永久清退 |

清退证据、未触发方案与解冻条件统一见 [§6](./6.搁置与低优先级方案.md) / [§14](./14.决赛优化状态与实施计划.md)。
