# 6. 冻结、搁置与无效优化

> **用途**：收纳不应进入近期排期的方案，避免已证伪项反复回流。活动队列见 [§2](./2.待落地优化Todo.md)，现行裁决与完整实施方案见 [§14](./14.决赛优化状态与实施计划.md)。
> **最后更新**：2026-08-01。

---

## 1. 🧊 已落地后冻结

这些实现保留在当前基线中，但没有新 profile 证据前不继续深化。

| 项 | 冻结原因 | 解冻条件 |
|----|----------|----------|
| BPM 64 分片 / S6 / Cleaner | `fetch_page` 已不再是主要 CPU 瓶颈 | BPM/evict ≥8% CPU 或显著缺页长尾 |
| S1/S3、WFG、`cv.wait` | 已解决原有持锁与误 abort 主矛盾 | 同类热点重新进入 Top-3 |
| S7.1、INLJ | 已有明确收益，继续扩张会增加并发正确性风险 | 索引/NLJ ≥10% CPU；INLJ 先完成 H3 |
| P2 `UPDATE_DELTA` | 约 +3.3%，正向但有限；日志格式已稳定 | WAL 字节成为第一瓶颈 |
| SER 谓词预编译 | 功能路径优化，排名固定 SI | SER 成为性能评测路径 |
| MIN 索引早停 / unpin 快路径 | 已解决 Delivery 扫描和根页写锁零推进 | 定向回归或新 profile 显示仍有同类问题 |
| MVCC sweeper / `recent_writes_` / 行锁回收 | 当前是内存稳定性基础设施，不是吞吐项目 | 长窗 RSS 仍持续增长 |
| 768MB BPM | 官方峰值 RSS 1.91GiB，余量不足 | RSS <1.7GiB 且缺页明确为瓶颈 |

注意：旧文档中的“后台 MVCC GC 未做”“`record_locks_` 未回收”已经过时；两者都已在当前 `chain_sweeper` 路径落地。

## 3. ⏸ 未达到实施门槛

| 项 | 为何暂不做 | 触发条件 |
|----|------------|----------|
| `page_lsn` 精确 flush | 改动 WAL/页时序，恢复风险高 | 全量 WAL 等待占 I/O ≥10% |
| 多活跃插入页 / `op_latch_` 分片 | 当前没有 insert latch 热点证据 | latch/futex ≥10% CPU |
| yacc/flex 重入化 | fast-parse 已覆盖排名热路径 | fallback parse 锁 ≥5% CPU |
| per-table dirty atomic | `any_mvcc_dirty_` 已挡住干净库开销 | `table_is_dirty` ≥3% CPU |
| 连接线程池 | TPC-C 使用 32 个长连接 | 建连/线程创建 ≥3% 或出现短连接门禁 |
| Cost-based join reorder | 当前核心连接已由 INLJ 处理 | 新 workload 三表以上 join 且 NLJ ≥10% CPU |
| Arena / 完整 SLRU | 未观察到分配或替换策略热点 | malloc/free 或 eviction 各 ≥8% CPU |

这些项目不是“永不做”，但只有触发证据出现后才从本表移回 [§2 活动队列](./2.待落地优化Todo.md)。实现草案和验收指标见 [§14 §5](./14.决赛优化状态与实施计划.md#5-未触发的实现计划)。

## 4. ❌ 已证伪或违规，永久退出活动队列

| 项 | 证据/原因 | 处理 |
|----|-----------|------|
| 固定 `sleep_for(80us)` 微批 | OJ 约 950→800 | 默认 0，不再上线 |
| 纯 wait-die | NewOrder abort 约 87%，tpmC 约 1200→400 | 使用 WFG |
| `RMDB_SCAN_FASTPATH` 当前实现 | churn 后 gap-EQ 漏行 | 默认关闭；不得以吞吐抵扣正确性 |
| 单连接 SI 物理快路径 | 可读到未提交物理写 | 保持禁用 |
| SI 陈旧写 rebase | 违反陈旧写必须 abort 的隔离语义 | 已移除 |
| 1GB BPM 决赛默认 | 2GiB 地址空间下内存风险 | 保持 768MB |
| 表名/字段/SQL 文本特化 | 违规且不可泛化 | 已删除，禁止恢复 |
| 批量“洗注释” | 无性能收益、扩大审计面 | 永久清退 |

失败过程保留在 [§3 历史日志](./3.方案A-C优化记录与tpmC评估.md) 和 [§4 WAL 复盘](./4.S5-WAL组提交深化.md)，只用于避免重蹈，不代表当前建议。
