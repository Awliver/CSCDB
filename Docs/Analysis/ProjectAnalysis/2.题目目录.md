## 题目四：查询优化与执行

**类型**：基础功能

**⚠️ 重要说明**：题目四不是简单的"输出计划树"，而是要求 **`logical_optimization` 真正改写 Plan 树的节点层级关系**（谓词下推到底层 Scan/Join，投影下推到 Join 子树），然后按**极其严格的格式规范**输出优化后的 Plan 树与运行时统计。

**主文件**：
- `src/optimizer/planner.cpp` — `logical_optimization()` 空实现，需填充**谓词下推**（将 Filter 条件下推到 Scan/Join 子节点）和**投影下推**（将 Projection 下推到 Join 子树减少中间列数），**真正修改 Plan 树结构**；`physical_optimization()` 需确保计划树结构正确
- `src/portal.h` — `convert_plan_executor` 需支持 `EXPLAIN ANALYZE` 的计划树遍历与输出生成；Plan 树需按规范排序输出（同层按 Filter→Join→Project→Scan；同类型按字典序）
- `src/execution/execution_manager.cpp` — `select_from` 需支持 `EXPLAIN ANALYZE` 模式：统计每个算子节点的运行时行数（Scan 的 rows=扫描总行数；Filter 的 rows=过滤后行数；Project 的 rows=投影后行数；Join 的 rows=连接结果行数；NLJ 右子树 rows = 左表行数 × 右表单次行数），并按规范格式写入 `output.txt`

**副文件**：
- `src/optimizer/plan.h` — 各类 Plan 节点定义（ScanPlan / JoinPlan / ProjectionPlan / SortPlan）
- `src/execution/executor_abstract.h` — 算子基类，需补充运行时行数统计字段（如 `rows_executed_`）
- `src/execution/executor_seq_scan.h`、`src/execution/executor_index_scan.h`、`src/execution/executor_nestedloop_join.h`、`src/execution/executor_projection.h` — 各算子需在执行时统计并暴露 `rows`

## 题目九：可配置的快照隔离与可串行化隔离级别

**类型**：基础功能

**⚠️ 重要前提**：题目九基于 **MVCC + SSI**（非经典 2PL）。运行时仍使用 `LockManager`（行锁 + **WFG 死锁检测**，见 Optimize §5）；SSI 危险结构检测在 `TransactionManager`。

**主文件**：
- `src/transaction/transaction_manager.cpp` — 在 begin/commit/abort 基础上扩展 MVCC + SSI：
  - `begin`：分配 start_ts（read_ts），初始化隔离级别（SI 或 SER）；SER 事务需初始化读集合、谓词读集合、写集合、rw 反依赖关系记录
  - `commit`：分配 commit_ts，使本事务写入对其他事务可见；清理临时状态
  - `abort`：清理 `undo_logs_` 和 `version_info_` 中该事务产生的版本链；该事务视为从未发生，其读写集合、rw 反依赖全部清理
  - **SSI 核心机制（需在 begin/commit/abort 及 DML 执行路径中内联实现）**：
    - SELECT 时：保存读集合（记录标识）和谓词读（查询条件/扫描范围）；检查其他事务已产生但当前快照不可见的写入，若会改变 SELECT 结果则建立 `current_reader ->rw writer`
    - INSERT/DELETE/UPDATE 时：将写操作影响的记录与其他 SER 事务保存的读信息比较，若满足其他事务读条件且该读事务快照不包含本次写入，则建立 `reader ->rw current_writer`
    - 每次新增 rw 反依赖后检测危险结构（`Tin ->rw Tpivot` 且 `Tpivot ->rw Tout`，满足 `Tin=Tout` 或 `Tout` 提交早于 `Tin`）
    - 形成危险结构时：新增该依赖的语句所在事务立即 abort，向客户端返回 `abort\n`
  - MVCC 辅助接口：`UpdateUndoLink` / `GetUndoLink` / `GetVersionLink` / `GetUndoLog` / `GarbageCollection`
- `src/transaction/watermark.cpp` — 实现 `AddTxn` / `RemoveTxn` / `UpdateCommitTs` / `GetWatermark`
- `src/execution/execution_common.h` — `ReconstructTuple()` 需根据 `undo_logs_` 链重建旧版本；`IsWriteWriteConflict()` 需检测写写冲突（同一逻辑记录上的并发写入）

**副文件**：
- `src/transaction/transaction.h` — UndoLink / UndoLog / TupleMeta 定义（已有）
- `src/record/rm_defs.h` — TupleMeta（ts_ + is_deleted_）定义（已有）
- `src/transaction/transaction_manager.h` — `version_info_` 全局版本链表（已有定义）
- `src/execution/executor_seq_scan.h`、`src/execution/executor_index_scan.h` — 扫描时需根据事务 start_ts + undo 链判断可见性
- `src/transaction/concurrency/lock_manager.cpp` — **框架遗留代码，题目九基于 MVCC + SSI 而非 2PL，无需实现具体加锁逻辑**
