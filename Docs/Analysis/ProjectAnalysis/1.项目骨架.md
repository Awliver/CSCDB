RMDB 是 C++17 实现的关系型数据库教学内核，采用**自底向上的分层架构**：

```
┌─────────────────────────────────────────────┐
│ 查询引擎（火山模型）：Parser → Analyze →     │
│ Optimizer → Portal → Execution              │
├─────────────────────────────────────────────┤
│ 事务与恢复：TransactionManager + LockManager │
│  + LogManager + RecoveryManager             │
├─────────────────────────────────────────────┤
│ 索引层：B+ 树（IxIndexHandle / IxScan）      │
├─────────────────────────────────────────────┤
│ 记录层：Slotted-Page（RmFileHandle / RmScan）│
├─────────────────────────────────────────────┤
│ 缓冲层：BufferPoolManager（分片）+ LRU       │
├─────────────────────────────────────────────┤
│ 磁盘层：DiskManager（页式文件 + WAL 预分配） │
└─────────────────────────────────────────────┘
```

**元数据中枢**：`SmManager` 管理 `DbMeta`（库/表/列/索引），经 `db.meta` 持久化。

**执行流水线**：`rmdb.cpp` TCP 收 SQL → **fast-parse（热路径）或** flex/bison → AST → `Analyze` → `Optimizer` → `Portal` → Executor → `QlManager`。

### JOIN 子系统

JOIN 不再使用“表名数组 + 扁平条件数组”表达，而是跨层保留树结构：

```text
JoinExpr AST
  → AnalyzedFrom（关系实例作用域；ON/WHERE 分离）
  → JoinPlan / FilterPlan（逻辑类型与物理算法分离）
  → NestedLoopJoinExecutor / IndexNestedLoopJoinExecutor
  → null_mask() 逐列传递到 Filter/Project/Aggregate/Sort/Limit/Union
```

Planner 只重排纯 INNER/CROSS 子树，LEFT/RIGHT/FULL 是语义屏障；Executor 对外连接生成真正的 NULL 掩码，而不是把零填充字节当作 NULL。完整设计见 [7.JOIN扩展架构](./7.JOIN扩展架构.md)。
