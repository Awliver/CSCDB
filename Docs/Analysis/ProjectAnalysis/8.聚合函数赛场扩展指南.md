# 聚合函数赛场扩展指南

## 结论

聚合正式链路统一为：

```text
SQL -> AggExpr -> AggregateInfo -> AggPlan -> AggExecutor -> Projection
```

`AggPlan`、哈希分组、`groups_`、`group_order_`、GROUP BY NULL bitmap、每组
`vector<AggState>` 和执行器迭代接口保持不变。原先基于 `TabCol::agg_type` 的
`QlManager::select_agg()` 旁路已经删除，新增聚合不要修改 `execution_manager.cpp`。

## 新增一个简单聚合

以能复用现有 summary 状态（`count/sum/min/max`）的函数为例，只修改两个固定区域：

1. 在 `src/common/aggregate_defs.h` 的 `RMDB_AGGREGATE_FUNCTIONS` 增加一行。
2. 在 `src/execution/executor_aggregation.h` 的 `AggExecutor::finalize()` 增加一个
   `case`。

注册行同时声明：

- SQL 名称；
- 可接受的参数类型；
- 是否接受 `*`；
- 是否接受 `DISTINCT`；
- 输出类型规则；
- 状态更新规则。

例如，一个数值 `RANGE(col) = MAX(col) - MIN(col)` 可以注册为：

```cpp
X(RANGE, "range", AGG_INPUT_NUMERIC, false, false, SAME_AS_ARGUMENT, SUMMARY)
```

然后只在 `finalize()` 相邻 switch 中计算整型或浮点差值。因为 parser 接受注册表中
的普通标识符函数名，Analyzer、HAVING 隐藏聚合、Planner schema、UNION schema 和
EXPLAIN 名称都无需再增加 `range` 分支。

如果新函数需要不同的中间状态：

1. 在 `AggState` 相邻区域增加状态字段；
2. 注册为 `CUSTOM`；
3. 在 `update_state()` 的 CUSTOM switch 增加一个 case；
4. 在 `finalize()` 增加一个 case。

除此之外不应修改 parser、Analyzer、Planner、AggPlan、Portal 或输出层。若发现必须在
这些文件写函数名 switch，说明扩展又绕开了注册表。

## 赛前固定测试矩阵

每个新聚合至少覆盖：

- INT、FLOAT，以及声明支持时的 CHAR；
- 无 GROUP BY、单列/多列 GROUP BY；
- 空输入；
- 输入 NULL 与 GROUP BY NULL；
- SELECT 中使用；
- 只在 HAVING 中使用（隐藏聚合）；
- UNION 元数据；
- 参数类型错误、非法 `*`、非法 `DISTINCT`；
- ORDER BY 聚合别名；
- 与已有多个聚合并列。

项目当前比赛方言约定：无值的普通聚合输出该结果类型的零值，而不是标准 SQL NULL；
新增函数应显式遵循或在题目要求变化时统一调整 `finalize()`。

## 仍需注意的边界

当前 SELECT AST 仍将普通列和聚合列分开保存，语法仅支持“普通列在前、聚合在后”。
本轮已经保证输出只包含 SELECT 中的普通列，并按该 SELECT 子序列输出，但若比赛要求
`SELECT SUM(v), k` 或任意交错顺序，需要再将两组 vector 合并成有序的
`select_items`；不要靠 GROUP BY 顺序猜测输出顺序。

`COUNT(DISTINCT col)` 当前按物理字节去重，INT 和定长 CHAR 赛题通常足够；若要求严格
浮点等值语义，应先规范化 `+0/-0`、NaN 等表示。
