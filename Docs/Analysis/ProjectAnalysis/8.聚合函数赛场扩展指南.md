# 聚合函数赛场扩展指南

## 结论

聚合正式链路统一为：

```text
SQL -> AggExpr -> AggregateInfo -> AggPlan -> AggExecutor -> Projection
```

`AggPlan`、哈希分组、`groups_`、`group_order_`、GROUP BY NULL bitmap、每组
`vector<AggState>` 和执行器迭代接口保持不变。原先基于 `TabCol::agg_type` 的
`QlManager::select_agg()` 旁路已经删除，新增聚合不要修改 `execution_manager.cpp`。

## 新增一个简单聚合

以能复用现有 summary 状态（`count/sum/min/max`）的函数为例，只修改两个固定区域：

1. 在 `src/common/aggregate_defs.h` 的 `RMDB_AGGREGATE_FUNCTIONS` 增加一行。
2. 在 `src/execution/executor_aggregation.h` 的 `AggExecutor::finalize()` 增加一个
   `case`。

注册行同时声明：

- SQL 名称；
- 可接受的参数类型；
- 是否接受 `*`；
- 是否接受 `DISTINCT`；
- 输出类型规则；
- 状态更新规则。

例如，一个数值 `RANGE(col) = MAX(col) - MIN(col)` 可以注册为：

```cpp
X(RANGE, "range", AGG_INPUT_NUMERIC, false, false, SAME_AS_ARGUMENT, SUMMARY)
```

然后只在 `finalize()` 相邻 switch 中计算整型或浮点差值。因为 parser 接受注册表中
的普通标识符函数名，Analyzer、HAVING 隐藏聚合、Planner schema、UNION schema 和
EXPLAIN 名称都无需再增加 `range` 分支。

如果新函数需要不同的中间状态：

1. 在 `AggState` 相邻区域增加状态字段；
2. 注册为 `CUSTOM`；
3. 在 `update_state()` 的 CUSTOM switch 增加一个 case；
4. 在 `finalize()` 增加一个 case。

除此之外不应修改 parser、Analyzer、Planner、AggPlan、Portal 或输出层。若发现必须在
这些文件写函数名 switch，说明扩展又绕开了注册表。

## 已定档的聚合函数与语义

当前正式支持：

| 函数 | 参数 | 输出 | 空输入/全 NULL | 备注 |
|---|---|---|---|---|
| `COUNT(*)`、`COUNT(col)` | 任意列或 `*` | INT | 0 | `COUNT(col)` 跳过 NULL |
| `COUNT(DISTINCT col)` | 任意列 | INT | 0 | 按当前物理值去重 |
| `MIN`、`MAX` | INT/FLOAT/CHAR | 与参数相同 | 类型零值 | 跳过 NULL |
| `SUM` | INT/FLOAT | 与参数相同 | 0/0.0 | 跳过 NULL |
| `AVG` | INT/FLOAT | FLOAT | 0.0 | binary64 累加后输出 FLOAT32 |
| `RANGE` | INT/FLOAT | 与参数相同 | 0/0.0 | `MAX-MIN` |
| `PRODUCT` | INT/FLOAT | 与参数相同 | 0/0.0 | 整型遵循当前 INT 输出宽度 |
| `VARIANCE` | INT/FLOAT | FLOAT | 0.0 | 总体方差，除以 `N` |
| `STDDEV` | INT/FLOAT | FLOAT | 0.0 | 总体标准差，`sqrt(VARIANCE)` |

`VARIANCE` 和 `STDDEV` 使用 Welford 在线算法，每组维护 `count/mean/M2`，避免
`E[x²]-E[x]²` 在大数值、低方差数据上发生严重消减误差。二者忽略 NULL，单元素组
结果为 0.0，暂不接受 `*` 或 `DISTINCT`。

赛场手测最小样例：

```sql
create table agg_stat (g int, v int);
insert into agg_stat values (1,1);
insert into agg_stat values (1,2);
insert into agg_stat values (1,3);
insert into agg_stat values (1,4);
insert into agg_stat values (2,10);

select variance(v), stddev(v) from agg_stat;
-- 总体方差 10，标准差约 3.1622777

select g, variance(v), stddev(v)
from agg_stat group by g order by g;
-- g=1: 1.25, 约 1.118034；g=2: 0, 0

select g, count(*) from agg_stat
group by g having variance(v)>1 order by g;
-- 仅输出 g=1
```

完整自动门禁为 `tests/local/variance_stddev_gate.py`。

## 其他可能赛题及修改文件

下面按“当前结构能否直接承载”列出边界。文件范围指最小合理修改面；若实现时出现更多
散落的函数名判断，应先检查是否绕过了注册表。

| 候选函数 | 主要难点 | 需要改动的文件 |
|---|---|---|
| `MEDIAN(col)` | 每组保存动态数组，finalize 排序；需先约定偶数个元素的结果类型 | `src/common/aggregate_defs.h`；`src/execution/executor_aggregation.h` |
| `MODE(col)` | 每组频率表；必须约定并列众数的确定性规则 | `src/common/aggregate_defs.h`；`src/execution/executor_aggregation.h` |
| 一元 `GROUP_CONCAT(col)` | 动态字符串、分隔符、最大输出长度和顺序 | `src/common/aggregate_defs.h`；`src/execution/executor_aggregation.h`；若输出长度不能用注册表固定表达，再改 `src/analyze/analyze.h` 的 `AggregateInfo::output_len()` |
| `ARG_MAX(value,key)`、`ARG_MIN(value,key)` | 两个不同类型参数，状态保存最佳 key 和对应 value | 下文“多参数聚合升级面”的全部文件 |
| `WEIGHTED_AVG(value,weight)` | 双参数绑定与类型检查，状态为 `sum(v*w)/sum(w)` | 下文“多参数聚合升级面”的全部文件 |
| `COVAR(x,y)`、`CORR(x,y)` | 双参数在线统计与数值稳定性 | 下文“多参数聚合升级面”的全部文件 |
| `PERCENTILE_CONT(value,p)` | 参数含常量、每组排序、插值 | 多参数升级面；另需允许聚合参数保存一般表达式/常量 |
| `AGG(...) FILTER (WHERE ...)` | 每个聚合携带独立过滤条件 | `src/parser/ast.h`、`src/parser/yacc.y`、生成 parser、`src/analyze/analyze.h/.cpp`、`src/optimizer/planner.cpp`、`src/execution/executor_aggregation.h` |
| 窗口函数 `... OVER (...)` | 输出仍保留每个输入行，不再是普通分组聚合 | 需要新增窗口 Plan/Executor，并修改 parser、Analyzer、Planner；不应塞进 `AggExecutor` |

单参数 `MEDIAN` 和 `MODE` 仍属于当前 CUSTOM 模板：注册一行，在 `AggState` 增加
容器，在 CUSTOM update/finalize 各加一个 case 即可。`GROUP_CONCAT` 若题目固定输出
上限也可留在这个模板中；否则它会触及输出 schema 契约。

多参数聚合不能只给 `AggState` 加字段。建议一次性将参数表示从单列升级为参数列表，
最小修改面为：

1. `src/common/aggregate_defs.h`：注册表增加参数个数和逐参数类型规则；
2. `src/parser/ast.h`：`AggExpr` 从单个 `col` 升级为参数表达式列表；
3. `src/parser/yacc.y`：增加聚合参数列表语法，并重新生成 `yacc.tab.cpp/.h`；
4. `src/analyze/analyze.h`：`AggregateInfo` 保存全部已解析参数及类型；
5. `src/analyze/analyze.cpp`：逐参数解析、类型检查、HAVING 隐藏聚合复用相同入口；
6. `src/optimizer/planner.cpp`：把所有聚合参数列纳入 child required columns；
7. `src/execution/executor_aggregation.h`：预绑定多个输入槽并完成状态转移；
8. `src/parser/test_parser.cpp` 和独立 Wire-v3 门禁：覆盖语法与端到端契约。

`AggPlan` 本身继续保存 `vector<AggregateInfo>`，通常无需因参数列表单独改结构。

## 赛前固定测试矩阵

每个新聚合至少覆盖：

- INT、FLOAT，以及声明支持时的 CHAR；
- 无 GROUP BY、单列/多列 GROUP BY；
- 空输入；
- 输入 NULL 与 GROUP BY NULL；
- SELECT 中使用；
- 只在 HAVING 中使用（隐藏聚合）；
- UNION 元数据；
- 参数类型错误、非法 `*`、非法 `DISTINCT`；
- ORDER BY 聚合别名；
- 与已有多个聚合并列。

项目当前比赛方言约定：无值的普通聚合输出该结果类型的零值，而不是标准 SQL NULL；
新增函数应显式遵循或在题目要求变化时统一调整 `finalize()`。

## 仍需注意的边界

当前 SELECT AST 仍将普通列和聚合列分开保存，语法仅支持“普通列在前、聚合在后”。
本轮已经保证输出只包含 SELECT 中的普通列，并按该 SELECT 子序列输出，但若比赛要求
`SELECT SUM(v), k` 或任意交错顺序，需要再将两组 vector 合并成有序的
`select_items`；不要靠 GROUP BY 顺序猜测输出顺序。

`COUNT(DISTINCT col)` 当前按物理字节去重，INT 和定长 CHAR 赛题通常足够；若要求严格
浮点等值语义，应先规范化 `+0/-0`、NaN 等表示。

## 定档结论

本轮聚合链路至此定档。对于“单参数、固定输出 schema、每组可独立维护状态”的新增
聚合，正式扩展面冻结为：

- `src/common/aggregate_defs.h`：声明名称和契约；
- `src/execution/executor_aggregation.h`：增加状态（需要时）、CUSTOM update（需要时）
  和 finalize；
- `tests/local/`：增加独立 Wire-v3 功能门禁。

Parser、Analyzer、Planner、HAVING、JOIN/LATERAL、Projection 和 Wire schema 已通过
注册表与 `AggregateInfo` 自动承接，不再为单参数聚合增加函数名特判。只有题目明确要求
多参数、变长 schema、FILTER 或窗口语义时，才按上面的升级面解冻结构。

正式收尾验收命令：

```bash
cmake --build build --target rmdb test_parser -j2
ctest --test-dir build -R test_parser --output-on-failure
python3 -B tests/local/range_product_gate.py
python3 -B tests/local/variance_stddev_gate.py
python3 -B tests/local/join_unique_agg_gate.py
```
